# ROLES.md — the org chart

The point of this OS: **one IC covers a full team's worth of functions.** This
table makes that literal. Each function is fulfilled by a skill, the registry,
the human, or is an honest "not yet."

| Function          | Normally a hire | How it's fulfilled here                              |
|-------------------|-----------------|-----------------------------------------------------|
| **Product**       | PM              | `draft-prd` skill + `product/` artifacts            |
| **Ops / Chief of staff** | CoS      | `weekly-synthesis` skill + the registry             |
| **Eng / QA sign-off** | Eng lead / QA | `launch-gate` skill                              |
| **Memory / knowledge** | Knowledge mgmt | `decisions/` + `feature-index.yaml`            |
| **Direction & taste** | Lead / founder | **The human** — priorities, judgment, go/no-go  |
| **Analytics**     | Data analyst    | *Not yet automated* — natural next skill (`metrics-pull`) + a `data-catalog.yaml` registry |
| **Design**        | Designer        | *Not yet automated* — `design/` folder is the seam  |
| **Strategy**      | Strategy/BizOps | *Not yet automated*                                  |

Two things are deliberately **not** delegated to the agent: **direction** (what
matters and why) and **judgment** (the go/no-go call). Everything else is a
function you can "hire" by adding a skill — without adding a person.
